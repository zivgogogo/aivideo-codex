# 映序：从获取代码到启动整个项目

本文件可以单独转发。读者无需已有代码或原作者的本地文件，按下面步骤即可获取代码、安装依赖并启动项目。

- 项目仓库：[zivgogogo/aivideo-codex](https://github.com/zivgogogo/aivideo-codex)
- 本文在线地址：[初始化与启动指南](https://github.com/zivgogogo/aivideo-codex/blob/main/docs/%E5%88%9D%E5%A7%8B%E5%8C%96%E4%B8%8E%E5%90%AF%E5%8A%A8%E6%8C%87%E5%8D%97.md)
- 默认使用 `main` 分支。仓库公开，克隆时无需登录 GitHub 或提供访问令牌。

## 1. 先准备什么

| 项目 | 要求 |
| --- | --- |
| Python | 3.10 或以上；新安装推荐选择 Python 3.13 系列 |
| Git | 推荐安装，用于克隆代码和之后更新；直接下载 ZIP 时可以不安装 |
| 网络 | 获取代码、首次安装依赖和调用 AI 服务时需要 |
| 浏览器 | 使用现代浏览器打开本机页面 |
| 百炼 API Key | 使用自己的阿里云百炼密钥；只启动页面、创建空白画布时可以暂不配置 |

安装入口：[Python 官网](https://www.python.org/downloads/)、[Git 官网](https://git-scm.com/install/)。安装完成后重新打开终端。

macOS 如果运行 `git --version` 提示缺少开发工具，可以执行 `xcode-select --install`，按系统提示完成命令行工具安装。

Ubuntu / Debian 用户在获取代码前，可以先安装基础环境和中文字体：

```bash
sudo apt-get update
sudo apt-get install -y git python3 python3-venv python3-pip fonts-noto-cjk
```

运行 `python3 --version` 确认版本不低于 3.10；系统自带版本过旧时，先安装满足要求的 Python。Windows 用户安装 Git 和 Python 3.13 后，确认 `git --version`、`py -3.13 --version` 可以执行。

项目使用 Python 提供网页和接口，**正常运行不需要 Node.js、npm、数据库、Docker 或独立前端开发服务器**。Python 依赖由 `requirements.txt` 管理，目前包含 Pillow 和 imageio-ffmpeg。视频工具由 imageio-ffmpeg 提供，通常不需另装系统 FFmpeg。

macOS 和 Linux 是目前的主要验证环境，GitHub 自动检查覆盖 Linux 的 Python 3.10、3.13。Windows 可使用下面的 PowerShell 命令；原生 Windows 尚未纳入自动测试。

## 2. 获取项目代码

### 推荐：用 Git 克隆

在准备存放项目的文件夹打开终端。macOS/Linux 使用终端，Windows 使用 PowerShell，执行：

```bash
git clone https://github.com/zivgogogo/aivideo-codex.git
cd aivideo-codex
```

之后的安装和启动命令都在这个项目根目录执行。正确的目录中应同时有 `README.md`、`requirements.txt`、`scripts/`、`backend/` 和 `frontend/`。

### 备选：不安装 Git，直接下载 ZIP

打开 [源码 ZIP 下载地址](https://github.com/zivgogogo/aivideo-codex/archive/refs/heads/main.zip)，解压后进入 `aivideo-codex-main` 文件夹。

ZIP 方式下载的目录名与 Git 克隆略有不同，后续操作相同。**不要只下载本文或只下载某个子文件夹**；运行程序需要完整源码目录。

## 3. 安装依赖并初始化

按自己的系统选择一种方式。

### macOS

先确认 Python 版本满足要求：

```bash
python3 --version
```

在项目根目录运行：

```bash
python3 scripts/setup_project.py
```

也可以双击根目录的 `初始化项目.command`。如果终端的 `python3` 版本过旧，而已经安装了 Python 3.13，可以改用 `python3.13 scripts/setup_project.py`。

### Ubuntu / Debian Linux

确认已按第 1 节安装基础环境，且 `python3 --version` 为 3.10 或以上，再在项目根目录执行：

```bash
python3 scripts/setup_project.py
```

其他 Linux 发行版请安装对应的 Python venv 支持及 Noto Sans CJK 字体。程序导出中文字幕时会查找 `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`。

### Windows PowerShell

先安装 Git 和 Python 3.13，重新打开 PowerShell，确认下面两个命令可用：

```powershell
git --version
py -3.13 --version
```

在项目根目录执行：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt tzdata
.\.venv\Scripts\python.exe scripts/setup_project.py --skip-install
```

Windows 补装 `tzdata` 是为了提供程序使用的 `Asia/Shanghai` 时区数据；这是 Python `zoneinfo` 的官方数据回退方式，参见 [Python 时区数据说明](https://docs.python.org/3.13/library/zoneinfo.html#data-sources)。

Windows 不使用 `.command` 文件，也不需要运行 PowerShell 的环境激活脚本；直接使用上述 `.venv` 内的 Python 即可。中文字幕导出需要 `C:\Windows\Fonts\msyh.ttc`（微软雅黑）；缺少该字体时，请先安装对应中文字体。

### 初始化成功会得到什么

命令正常结束时会提示“初始化完成”。它会：

1. 创建或复用 `.venv`，安装或检查 Python 运行依赖。
2. 从 `.env.example` 创建本机 `.env`，已有配置会保留。
3. 准备 `production/canvas-projects/`、`production/projects/` 和 `outputs/`。
4. 创建没有人物、剧集和素材的空白工作台项目 `production/projects/default/`。

重复执行初始化不会重置已有项目，不会覆盖已有 `.env`，也不会调用 AI 生成服务。仓库不附带原作者的剧本、图片、视频或制作进度；初次打开项目为空是正常情况。

## 4. 配置自己的 AI 密钥

需要 AI 规划、人物提取、图片或视频生成时，在 [阿里云百炼控制台](https://bailian.console.aliyun.com/) 获取自己的 API Key，并确认账号具备所选模型的使用权限。

用文本编辑器打开**项目根目录的 `.env`**，不是 `.env.example`，也不是 `.env.txt`。将模板中的密钥占位内容替换成自己的密钥：

```dotenv
DASHSCOPE_API_KEY=替换成你自己的百炼密钥
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/api/v1
DASHSCOPE_LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_LLM_MODEL=qwen-plus
```

上面是模板中的默认地址。Key、接口地域、业务空间和模型权限应与自己的百炼账号一致；其他地域或业务空间请按 `.env.example` 中的说明修改。图片/视频接口和 LLM 接口的地址格式不同，不要互相替换。

macOS 可以用 `open -e .env` 打开文件；Linux 可以用 `nano .env`；Windows 可以用 `notepad .env`。

程序自动读取配置，**不需要执行 `source .env`**。系统中已设置的同名环境变量优先于文件中的值。修改 `.env` 后，需要重启服务才会生效。

未配置有效密钥时仍可以启动页面和创建空白画布；调用模型的功能需要有效配置，并按服务商账号的实际规则计费。

## 5. 启动整个项目：一个服务即可

### macOS / Linux

在项目根目录执行：

```bash
.venv/bin/python -m backend serve --port 8765
```

### Windows PowerShell

```powershell
.\.venv\Scripts\python.exe -m backend serve --port 8765
```

看到终端输出本地服务地址后，在浏览器打开：

| 地址 | 页面 |
| --- | --- |
| http://127.0.0.1:8765/ | 主画布入口 |
| http://127.0.0.1:8765/canvas | 主画布入口的另一地址 |
| http://127.0.0.1:8765/studio | 传统制作工作台 |

这条命令同时启动后端、画布业务和工作台业务，并由同一服务提供前端页面。**不需要再开一个前端服务，也不需要为了完整启动同时运行 8766 端口。**

命令行启动后需保留该终端窗口；停止服务时在该窗口按 `Ctrl+C`。本服务绑定本机地址，不会自动部署为公网网站。

macOS 也可双击 `启动短剧工作台.command` 启动完整服务，它会先打开 `/studio`；需要主画布时访问同一端口的 `/canvas`。

### 可选：只启动画布

如果只使用画布，可以用下面的方式替代完整服务：

```bash
.venv/bin/python -m backend serve --canvas-only --port 8766
```

Windows 将 `.venv/bin/python` 换成 `.\.venv\Scripts\python.exe`。打开 http://127.0.0.1:8766；macOS 也可双击 `启动短剧画布.command`。

只启动画布时不接管传统工作台的制作任务。日常使用选择一种启动方式即可，同一项目不要同时交给多个服务进程修改。

## 6. 第一次打开后怎么使用

1. 打开画布页面，在项目列表里创建“空白画布”，确认可以进入空白项目。
2. 可以添加图片卡、视频卡，编辑 Prompt，或上传自己的本地素材。
3. 需要按剧本制作时，通过画布的新建项目入口导入自己的 TXT、Markdown 或 DOCX。
4. 使用人物提取、导演规划和生成时，先完成密钥配置。

画布项目和传统工作台项目分别保存。画布中导入剧本不会自动把剧集复制到传统工作台；首次安装的 `/studio` 显示没有剧集是正常现象。新用户以画布作为创作入口即可。

如果已有符合工作台格式的本地项目 JSON，可以显式初始化一个工作台项目：

```bash
.venv/bin/python -m backend init --project production/projects/my-project --seed /path/to/your-project.json
```

此命令需要自行准备合法的工作台数据文件，不能把普通剧本文本直接作为 `--seed` 输入。之后用 `--project production/projects/my-project` 启动完整服务。

### 判断是否启动成功

- 主画布能够打开，页面能创建空白项目。
- http://127.0.0.1:8765/api/state 能返回包含 `project`、`episodes`、`jobs` 等字段的 JSON。
- http://127.0.0.1:8765/api/canvas/projects 能返回画布项目列表；刚安装时列表可以为空。

这些检查不需要提交付费生成任务。

## 7. 数据存在哪里

| 路径 | 内容 |
| --- | --- |
| `.env` | 本机密钥及可选项目配置 |
| `.venv/` | 本机依赖环境 |
| `production/canvas-projects/` | 自己的画布项目和对应素材 |
| `production/projects/default/` | 默认空白工作台项目 |
| `production/projects/其他名称/` | 自行初始化的其他工作台项目 |
| `outputs/` | 独立工具的输出；具体制作素材也可能保存在对应项目目录下 |

以上运行数据由本机生成，受 Git 忽略规则保护。换电脑时应另外备份和恢复 `.env`、项目目录和外盘素材；重新克隆代码不会恢复已有制作进度。

源码文件夹的详细分工见仓库根目录的 `项目目录说明.md`。

## 8. 以后怎么更新

### 页面一键更新（推荐）

通过 Git 克隆、在 `main` 分支并使用项目 `.venv` 启动的用户，可以在画布和传统工作台右上角点击 **“检查更新”**。

1. 页面打开时自动连接本项目的 GitHub `main` 分支，之后每 5 分钟检查一次；回到页面时也会检查。只检查版本，不会自动安装。
2. 有更新时，按钮变为“发现新版本”。打开窗口可查看当前版本、最新版本及最近的提交说明。
3. 保存其他窗口的编辑，等待所有生成任务完成，只保留一个本项目服务，然后点击 **“更新并重启”**。
4. 程序备份旧代码、快进更新 Git 版本；依赖清单有变化时安装依赖，随后重启原端口、原项目的服务。页面连接恢复后自动刷新。

维护者只需把代码推送到 [公共仓库](https://github.com/zivgogogo/aivideo-codex) 的 `main` 分支；其他电脑上的安装便能检测到。同一安装中的不同画布项目共享程序版本，更新后一起使用新代码。Fork 或更换了 `origin` 的安装不会自动切回本仓库。

更新保留 `.env`、`production/`、`outputs/`、`local/` 中的配置和制作数据。若新版本意外包含这些路径，或新增文件会覆盖本地同名文件，更新会停止。未提交的源码修改、本地分支分歧、未完成的任务、多个服务同时运行，也会阻止更新并提示处理方法。

更新记录位于本机 `production/.updates/`，不上传 GitHub。每次记录包含旧代码 `before.bundle`、依赖清单 `dependencies.txt`、更新进程 `worker.log`、重启日志 `server.log` 和操作计划。启动失败时会尝试恢复旧代码和旧依赖并重启；若恢复失败，请查看日志，再手动初始化和启动。代码备份不代替自己的素材备份。

### 旧版本首次获得按钮 / 手动更新

尚无更新按钮的旧版本，先让生成任务完成、保存项目并停止所有服务，再在项目根目录执行一次：

```bash
git pull --ff-only
python3 scripts/setup_project.py
```

然后按第 5 节重新启动，之后可在页面更新。Windows 第二条改为 `.\.venv\Scripts\python.exe scripts/setup_project.py`。

如果提示本地代码修改或分支分歧，先保留并处理这些修改，再更新；不要通过删除制作数据解决代码冲突。

### ZIP 安装

ZIP 下载的目录没有 Git 历史，第一版一键更新不支持这种安装。推荐重新 Git 克隆并初始化，再迁移自己的 `.env`、`production/`、`outputs/` 及需要的本地资料；外盘链接按自己的电脑恢复。也可以重新下载源码并自行迁移数据。页面会明确显示当前安装不能一键更新。

## 9. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 找不到 `git`、`python3` 或 `py` | 安装第 1 节对应工具，重新打开终端，并检查版本 |
| Python 版本过旧 | 使用已安装的 Python 3.13 执行初始化；后续始终使用项目 `.venv` 内的 Python |
| `No module named backend` 或找不到 `requirements.txt` | 当前目录不对；先进入包含 `README.md` 的项目根目录 |
| 缺少 `PIL` 或 `imageio_ffmpeg` | 重新运行第 3 节初始化，并确认启动时使用 `.venv` 内的解释器 |
| Linux 报 `ensurepip`/`venv` 不可用 | 安装 `python3-venv`；使用特定版本 Python 时安装其对应的 venv 包 |
| Windows 报 `ZoneInfoNotFoundError` | 用 `.\.venv\Scripts\python.exe -m pip install tzdata` 补装时区数据 |
| 导出时提示没有中文字体 | Linux 安装 `fonts-noto-cjk`；Windows 检查微软雅黑字体；macOS 使用系统已有中文字体 |
| `.env` 修改后仍使用旧配置 | 停止并重启服务；检查进程环境变量是否覆盖了文件值 |
| AI 调用返回鉴权、地域或模型权限错误 | 检查自己的 Key、接口地址和模型权限，核对服务商返回的具体错误 |
| 8765 端口被占用 | 检查是否已有本项目服务；也可使用 `--port 8875`，页面地址同步改为 8875 |
| 初始化提示现有 `.venv` 不完整 | 保留并重命名旧环境目录后重新初始化；不用删除 `.env` 或制作项目 |
| 页面能打开但没有任何剧集 | 初始项目本来为空；在主画布导入自己的剧本 |

如需反馈问题，请附操作系统、Python 版本、所执行的命令和报错内容，不要附真实密钥或整份 `.env`。
